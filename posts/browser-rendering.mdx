주소창에 URL을 입력하고 엔터를 누르면, 브라우저는 서버에서 받은 바이트를 화면의 픽셀로 바꾸는 일련의 과정을 거친다. 이 과정을 **크리티컬 렌더링 경로(Critical Rendering Path)** 라고 부른다.

## 1. 파싱 — DOM과 CSSOM

브라우저는 HTML을 위에서부터 읽으며 토큰화하고, 노드 트리인 **DOM(Document Object Model)** 을 만든다. 동시에 CSS를 파싱해 **CSSOM(CSS Object Model)** 을 구성한다.

```html
<p>Hello <span>world</span></p>
```

이 마크업은 `p` 요소 아래 텍스트 노드와 `span` 요소가 자식으로 붙는 트리가 된다.

## 2. 렌더 트리

DOM과 CSSOM을 결합해 **렌더 트리**를 만든다. 이때 `display: none`인 요소는 렌더 트리에서 제외된다. 화면에 그려질 요소만 남는다는 점이 핵심이다.

## 3. 레이아웃(리플로우)

각 노드의 정확한 위치와 크기를 계산한다. 뷰포트 기준의 상대 단위(`%`, `vw`)가 픽셀로 확정되는 단계다.

- 요소의 크기·위치가 바뀌면 **리플로우**가 발생한다.
- 리플로우는 하위 트리 전체에 영향을 줄 수 있어 비용이 크다.

## 4. 페인트와 합성

계산된 정보를 바탕으로 픽셀을 채우고(페인트), 여러 레이어를 겹쳐 최종 화면을 만든다(합성). `transform`, `opacity`처럼 합성 단계에서만 처리되는 속성은 리플로우·리페인트를 건너뛰어 **가장 저렴한 애니메이션 속성**으로 꼽힌다.

## 정리

파싱 → 렌더 트리 → 레이아웃 → 페인트 → 합성. 성능 최적화는 결국 이 경로에서 **비싼 단계(레이아웃·페인트)를 얼마나 피하느냐**의 문제로 귀결된다.
